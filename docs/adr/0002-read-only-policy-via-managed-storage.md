# ADR-0002 — Read-only policy via managed storage; no writable rule store

**Status:** accepted

## Decision

Policy arrives through `storage.managed` from a file generated by a config
repository. The extension has **no writable rule store**: `storage.sync` is
unused, and "remember" writes a session-scoped override plus a snippet to paste
into the repo.

## Why

F3 (sync resurrection) and F5 (seeding drift) are both diseases of a writable,
syncing store:

- A rule deleted in one of two stores comes back from the other; deleting both
  is _still_ not enough without a tombstone; a third machine can re-upload
  during the cleanup.
- A one-shot seed means the repo and the profile drift in **both** directions,
  and neither is automatically the truth.

Managed storage removes the seeding step entirely — the file _is_ the source,
re-read at every extension start. And a store nothing can write is a store
nothing can resurrect.

The session override matters as much as the read-only part: the incumbent's
"remember my decision" silently **moved** a pin instead of deleting it, which is
how F1 came back after it was fixed. An override that dies with the browser
cannot do that.

## The cost, stated plainly

Managed storage is **not live**. Firefox reads the native manifest once per
extension start; there is no `onChanged` and no watcher. The seed idea "the repo
is the truth, live" is half false, and all three panel designs independently
rejected that half.

We pay it with visibility rather than denial: the popup shows the loaded
revision and its age, offers Reload, and the emergency stop is Pause (session)
or disabling the add-on — never an emergency config edit.

## Alternatives rejected

- **`storage.sync` with the repo as a mirror.** Reintroduces F3 exactly.
- **A file watcher.** Does not exist for managed storage in Firefox.
- **Native messaging host to push config.** An installer, a second moving part,
  and a much harder AMO review — for liveness we can survive without.
